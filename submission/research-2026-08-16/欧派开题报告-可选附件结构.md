# 欧派命题：可选附件结构

> 目标：用 4 页左右的 PDF 证明方案有真实用户路径、数据结构和落地边界。
>
> 这不是必须交的内容；但报名表明确把补充材料作为加分项，做一份干净的附件比堆很多文字更有用。

## 封面页：一句话问题与一句话方案

**标题建议：**

> 从“说不清想要什么”到“敢确认这一版”：欧派 AI 家装共识层

**左侧放问题：**

- 客户偏好模糊，设计师反复追问；
- 方案好看不等于客户相信能落地；
- 确认后变更会带来报价、工期和服务争议；
- 下游系统需要结构化输入，而不是一张效果图。

**右侧放方案：**

视觉化对话 -> 点选修改 -> 设计意图 JSON -> 变更影响说明 -> 客户确认版本 -> 设计师复核与下游交接

## 第 2 页：客户体验流程图

做成横向 6 步，尽量用一张小户型或客厅示意图，而不是大段文字。

1. **最低门槛表达**
   “四个人住，想要欧式，但不想显得压抑。”
2. **视觉化首问**
   AI 给出两个生活方式方向，并问一个高信息量问题。
3. **看见候选空间**
   使用企业既有 3D 方案或渲染图。
4. **点一下就能改**
   点击电视墙、柜体、灯光、布局，说或选“我想更亮”“储物更多”。
5. **先看影响再保存**
   显示预算区间、工期、材料或工艺、需设计师复核项。
6. **确认版本**
   客户确认关键边界；设计师收到可执行共识单。

页面角标应注明：

> “点选改动”不是单独创新点；创新在于每次改动都形成可确认、可解释、可下传的版本。

## 第 3 页：系统与数据流图

建议画成三层。

### 客户层

- 自然语言、语音、图片参考；
- 方案卡片；
- 3D 图热点点选；
- 版本对比与确认。

### 飞书共识层

- Aily：意图澄清、结构化输出；
- 多维表格：需求、版本、关键对象、变更、责任人；
- 自动化或工作流：通知、复核、异常处理、留痕；
- 低代码：客户和门店页面。

### 企业既有能力层

- 3D 设计和渲染；
- 报价与选材；
- BOM、排产、安装、售后。

中间放一个简短的结构化信息卡：

    偏好：欧式、温暖、储物多
    约束：四人居住、公共区开阔
    已确认：电视墙材质、收纳方案
    待复核：精确报价、工期
    当前版本：v3

## 第 4 页：试点方案、指标与边界

### 建议试点

先选一个空间或单品类，不做整家全链路。候选：

- 客餐厅方案；
- 定制衣柜；
- 厨房；
- 由欧派导师建议的高频场景。

### 拟验证指标

| 指标 | 为什么重要 | 试点观察方式 |
| --- | --- | --- |
| 首次方案到客户确认的轮次 | 看是否减少无效沟通 | 对比试点前后版本数 |
| 设计师重复澄清时长 | 看意图 JSON 是否有用 | 设计师工时记录 |
| 确认后重大变更率 | 看确认机制是否有效 | 变更表和版本日志 |
| 报价复核耗时 | 看是否减少前端信息缺失 | 报价任务耗时 |

### 明确边界

- 不替代专业设计师；
- 不新建 3D 渲染或生产排程系统；
- 不承诺 AI 自动精确报价；
- 不在未经企业授权时访问真实订单或客户隐私数据；
- 所有对接先以 API 或文件导入的试点假设表述。
