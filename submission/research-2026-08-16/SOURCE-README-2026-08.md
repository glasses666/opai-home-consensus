# 欧派 AI 家装共识层

> 用可视化对话、对象级修改、版本确认与影响说明，把客户的模糊偏好转化为可执行、可追溯的家装共识。

这是为 **2026 AI 先锋未来人才大赛** 欧派家居企业命题整理的开题方案与研究材料。项目不试图重新开发一套 3D 家装、报价或生产系统，而是在客户、导购、设计师与欧派既有系统之间增加一层轻量的“共识层”。

本 README 只说明本地工作区、材料和复算入口。赛程状态、决策、Coach 沟通和跨会话交接统一维护在 AgentVault 的 `PRJ-2026-008-oppein-ai-home-consensus` 项目库。

## 为什么不是再做一个 AI 生图工具

客户真正困难的通常不是“看不到一张漂亮效果图”，而是：

- 很难把“这里不太对”“希望开阔，但收纳不能少”说成设计师能直接执行的要求；
- 每次修改会影响多少空间、收纳、预算与工期，并不透明；
- 反复改图后，客户、导购、设计师和下游系统可能使用不同版本；
- 客户觉得满意，不等于方案已经满足报价、工艺和生产约束。

因此，方案的核心不是让模型“一次猜中”，而是让系统知道：**什么可以继续探索，什么不能违背，什么已经确认，以及一次修改需要付出什么代价。**

## 方案流程

```text
视觉化首问
  -> 两个取舍明确的候选方向
  -> 客户点选空间对象并用短句表达不满
  -> AI 转为硬约束、软偏好、未决项和已确认项
  -> 只修改相关对象并保留上一版本
  -> 展示空间、收纳、预算、工期与复核影响
  -> 客户确认视觉和功能版本
  -> 设计师确认生产可执行版本
  -> 接入既有 3D、报价、BOM 和生产系统
```

飞书在方案中承担意图澄清、结构化记录、版本协作、任务通知和外部系统连接，不承担专业 3D 渲染、精确报价或生产排程。

## 最小试点

首期只选择“小客厅电视墙”这一高频场景：

1. 客户在两个取舍明确的 3D 方案中开始选择，而不是填写长问卷；
2. 客户点击墙柜、电视区或沙发，以语音或短句提出局部要求；
3. 系统生成结构化意图 JSON、版本差异和变更影响卡；
4. 未决项不能进入下游，确认后的版本由设计师复核；
5. 通过接口或文件导入复用欧派既有设计、报价和生产能力。

拟记录的试点指标包括：首次确认轮次、设计师重复解释时长、确认后重大变更率、版本错用次数。所有指标均为待验证项，不是已实现效果。

## 研究与验证

- 对 36 条小红书、B 站公开表达进行匿名化和多标签编码，用于识别需求类型，不用于推断消费者总体比例；
- 以公开案例中的 3.1 米客厅参数建立电视墙几何对比；
- 计算显示：柜深减少 50 毫米只增加 50 毫米净距；低柜与双侧高柜可降低立面占用，但客厅本地几何储物约下降 42.9%；
- 该结果仅为几何推演，不代表欧派真实报价、工程数据或业务提升。

## 数据与内容边界

- 本项目是参赛阶段的研究方案，不代表欧派家居官方立场，也未接入欧派内部系统或业务数据；
- 公开样本只用于发现需求信号，保留可核验来源，不保留分析表中的用户名和用户 ID；
- 仓库不分发原始社交平台截图目录，避免无必要地公开第三方用户名、头像与页面信息；
- PDF 中的少量公开页面节选仅用于说明研究情境，权利归原作者与平台所有；
- 未经企业验证，不承诺转化率、返工率或交付周期的具体提升。
