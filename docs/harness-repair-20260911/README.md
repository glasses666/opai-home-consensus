## 一、真实退化路径

`REPRO-TRACE.json` 原件未修改。它记录的 `preserve_object` 和 `no_new_objects` 是正确的，不能把根因笼统归为“抽取错了约束”。退化发生在后面：模型自行认为书桌不必移动；当时观察没有足够明确的入口/家具关系与合法布局候选；工具需要模型自行选择位移；系统强调小尝试；终止门只证明命令合法，没有检查换色是否解决“像工位”，也没有检验“光不再像办公室”是否有事实依据。两次真实模型请求后就被 `legal_preview` 接受。

因此本轮修复不是要求用户补“可以移动”“请不要只换色”，而是增加可核查的观察、可执行的几何选项、独立设计复核及带具体失败证据的修正循环。

交接 trace 的附加说明列出了 `object-flex-chair`，但上传候选的实际 canonical scene 没有这把椅子。本轮以真实场景为准，没有补造椅子来满足叙事。

另外发现独立的呈现风险：Pascal 拒绝拖动中的快照替换时，旧代码只 catch 后丢弃，可能让 canonical scene 已变而画面未变。本轮改为有限重试，耗尽后明确报错和手动重试，不能只显示“已修改”。

## 二、落地修复

### 约束与场景原子性

| 用户表达 | 内部合同 | 允许 | 禁止 |
|---|---|---|---|
| 书桌要留 | preserve_object | 在原有能力与规则内移动、旋转、换材质 | 删除对象 |
| 书桌留在原位 | lock_transform | 许可的材质变更 | 改位置与方向 |
| 书桌什么都别动 | lock_object | 只读 | 对该对象的任何属性修改 |

机械校验以 before/after 的真实实体为准，未知对象范围报错；历史空范围代表全部现有对象，不能解释为空限制。硬约束不随对话条目数量自动失效。被拒绝的候选不能偷偷撤销跨轮限制，旧材质意向自动调和也必须经过独立复核才可成为可信状态。

新增 `objects.setTransforms`，把一组家具位置/转向作为**一个 SceneCommand**写入：逐件核对能力，最终整体几何只校验一次。这样合法的家具互换不会被中间态碰撞挡住，也不能出现前半组成功、后半组失败。撤销一条命令恢复整组。保存/重放仍使用同一版本系统，没有第二个场景真相。

### 几何观察与工具

`inspect_room` 现在提供门窗位置、窗台/门扇、房间边界、家具足迹、最短足迹间距、入口向内角度、简单遮挡、对象权限与明确的测量限制。

`explore_layout` 是有界、只读的几何搜索，对模型指定的一或两件现有可移动家具返回多种合法组合；不是固定房间布局，也不替模型选择设计目标。`apply_layout_option` 只接受本回合观察过的 optionId，且绑定完整序列化基础场景。场景过期、ID 编造或锁定目标都失败。

新增门扇阻挡拒绝与基于实际窗台/窗头高度的窗前概念避让。窗前 150mm 是代码明确标注的 **concept planning** 策略，不是法规净距、采光模拟或施工保证。边界内的凹形房间也检查整条家具边是否跨过凹口，而非只看角点。

### 设计质量闭环

生产默认用同一真实 DeepSeek provider 发起独立 review 调用，不用 ChatGPT 的回答或测试 fixture 当评审结果。复核六项：约束含义、事实依据、需求匹配、变化可察觉性、解释真实性、追问价值。要求实际变化 factId 引用；规划者自己发明的 factId 不算证据。

单件明确换色可以通过，不强迫移动；很多动作仍可因偏题而拒绝。失败把实际 before/after 差异、具体问题与新观察反馈给模型。完全相同的失败物理候选不能重复送审直到随机通过。独立复核仍可能与规划模型共享偏差，必须用 live A/B、holdout 与人眼复核校准，不能把模型打分当成客观设计真理。

预算：最多 6 个规划步骤、12 次产品回合模型请求，默认总截止 120 秒；每次实际调用均独立记录。该结构通常增加一次或更多模型调用，本环境没有真实延迟/成本改善证据。

### 工作台与恢复

真实阶段通过 NDJSON 传回“读取、规划、校验、复核、修正、预览”；没有定时编造百分比。取消中断服务端模型请求，客户端丢弃迟到/截断响应；失败可重试。失败模型尝试有鉴权的本地追加日志，不因为事务失败而消失。

新会话有界重试复用同一个创建 ID；已有项目 404/403 不会偷偷变成新项目。`npm run dev:experience` 同时启动匹配的本地 BFF 和 Vite，避免前端代理指向未启动服务；这只修复可控本地入口与恢复路径，不声称已诊断或修复线上反向代理的 502。

差异列表使用房间、家具名称和可读墙面定位，不暴露内部 ID。共享墙只定位实际改变的一侧，不误跳到未改变的宿主房间。真实渲染同步失败明确可见。家庭背景可跳过；填写内容先成为待发送草稿，不自动变成硬约束，预算和风格问卷不挡在普通 AI 入口之前。

## 五、应用和最小本机验证

在指定基线的干净工作分支应用补丁，不使用 main，不强推。先 `git apply --check /你的下载目录/OPAI-Harness-Repair-20260911.patch`，再用相同路径 `git apply`。changed-files ZIP 是同一改动的另一种交付，不必重复覆盖。现有未提交工作请先隔离到独立工作树，补丁不会替你丢弃它们。

在本机已配置真实密钥的环境、仓库 `app` 目录执行最小模型验证：

```bash
npm run verify:harness:live -- --variants=B --cases=core-repro,h-flex-rest --max-requests=24
```

脚本只读取本机现有 `DEEPSEEK_API_KEY` 环境或既有 `.env.local`；不会要求写进对话/补丁/仓库。缺失时立即停止，不 fallback。模型固定为 DeepSeek-v4-flash、thinking enabled、reasoning effort high；实际响应型号也记录并核验。原始 trace 曾报告 `deepseek-flash`，因此只接受该已见别名或明确 v4-flash；其他/缺失型号中止而不冒认。

小批真实 A/B（A 必须能从本机 Git 读到完整 `fc742b7bd8f1fcf44dcce3a33d6dafb04dde0b1b` 对象）：

```bash
npm run verify:harness:live -- --variants=AB --cases=core-repro,d-desk-retain,h-flex-rest --max-requests=40
```

A 从真实基线 `git archive` 加载，不是把 B 的新门关闭冒充旧系统。两组使用相同输入、初始场景和模型参数，交替顺序；同一额外独立模型调用作盲审，但不替代人类评估。达到请求上限如实中止，首次错误不覆盖。

输出默认保存到本机私有 `.data/harness-eval/<时间与随机后缀>/`。预期字段见 `CONTRACT.md`。若要运行全部 development 或 holdout，使用 manifest 中的场景 ID 列表分小批运行；不要在看过 holdout 失败并据此调参后继续称其“未见过的 holdout”。

完整源仓库且依赖可安装时，先运行：

```bash
npm ci
npm run test:harness
npm test
npm run build
```

真实浏览器需 Python Playwright 与可用 Chrome/Chromium。启动本地产品（只读 QA 探针仅开发模式启用）：

```bash
VITE_OPAI_QA_PROBE=1 npm run dev:experience
```

另一个终端仍在 `app` 目录运行：

```bash
python3 scripts/qa-harness-browser.py
```

脚本仅允许 localhost；每视口最多 4 次合成用户回合，从真实首页新会话进入，检查实际 mesh 的世界矩阵、材质、模型就绪，完成预览/撤销/保留/保存 V2/刷新，记录控制台和关键加载失败。只拦截飞书讨论写入，不执行真实外部意见操作。输出的“机械通过”仍要求人工查看前后截图是否明显、合意。前端与 BFF 的 sourceFingerprint 应与本报告相同。

## 六、兼容性与未消除风险

新增成组命令需要前后端同时更新；旧版客户端不保证能重放新命令，不能只部署一侧。旧保存版本不迁移，不改默认户型和素材。turn 响应新增 `conversationDelta`（本轮两条）替代反复返回全部 `conversation`；完整历史仍从鉴权项目 GET 获取，当前产品 UI 不依赖旧 turn 的全量历史字段。单回合流限制 8MiB、完整项目 JSON 限制 64MiB；长期大项目仍需后续分页/存储评估。

有界布局搜索不是穷尽优化，当前一次选 1–2 件家具，入口角度/最短足迹间距也不是完整动线与人体工学算法。独立复核仍是模型判断；延迟与额外费用待 live 测量。现有旧解析规则未在本轮大面积删除，避免破坏已覆盖的明确指令合同；新开放设计质量链没有添加针对演示句的关键词或房间专用 if/else。新数据输入与长对话下的复杂语义仍必须用未见输入检验。

本轮没有提交生产配置、发布应用、真实飞书数据、密钥、受限 Fab 二进制、原始视频或用户已确认的家具变更。最终本机依赖、构建与隐藏桌面渲染已可用；手机自动化仍因当前 Python 环境缺 Playwright 未执行，生产与真实飞书闭环也未在本轮触碰。
