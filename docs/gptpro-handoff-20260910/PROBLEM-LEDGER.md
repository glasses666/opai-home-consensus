# 当前问题与验收目标

## P0：Harness 抑制了设计能力

### 复现 A：正确识别约束，但只做了两处低价值换色

用户在儿童房 / 书房场景输入：

> 回到家还是像坐在工位，我想放松一点，但书桌要留下，先别加大件。

真实 DeepSeek 已开启 reasoning，模型正确抽取：

- 目标：让书桌所在空间放松、不像工位。
- 硬约束：保留书桌；不新增大件。

最终却把“保留书桌”擅自升级为“书桌位置也不用挪”，只执行：

1. `surface-wall-reference-10` 改暖灰微水泥。
2. `object-flex-bed` 从雾绿织物改暖亚麻。

这两个动作规则合法，却没有处理工作区的视觉主导、进门视线、书桌方向、工作/休息分区，因此用户明确认为“改变太少，而且不太符合要求”。完整脱敏 trace 见 `REPRO-TRACE.json`。

期望：`preserve_object` 只保证对象仍存在；除非用户明确说“原位不动”，否则可移动/旋转。Agent 应在一次关键澄清与一组显著、原子、可撤销的空间尝试之间做判断，不能用低相关换色假装解决生活问题。

### 复现 B：房间已经明确，仍给出空泛追问

用户输入“感觉厨房太挤了”，实际 DeepSeek 回复“你希望优先解决的是哪个具体场景？”。当前房间事实和用户点名房间已经足以缩小问题；如果需要澄清，应问能改变方案的具体分歧，例如“更困扰你的是两个人同时操作，还是进出时会互相让路？”，不能把识别工作重新推给用户。

### 对话风格问题

- 过度解释、像问卷或心理诊断，不像设计师一起看房。
- 普通人被迫学习厘米、坐标、材质 ID 或风格术语。
- 简单请求经常被 Harness 诱导成 `clarify`，而不是先观察事实后做可撤销尝试。
- 系统强调“谨慎”和“只问一个问题”后，出现“每轮都问一个问题”的机械行为。
- 规则合法性被误当成设计质量；只要没有碰撞，低价值动作也会显示为成功。

## P0：缺少“方案是否真正回应需求”的闭环

当前确定性验证能拒绝未知对象、越界、碰撞和能力不支持，但没有评价：

- 动作是否直接作用于用户点名的对象/区域。
- 动作组合是否足以形成可见变化。
- 解释的因果是否与实际命令一致。
- “保留对象”与“冻结位置/材质/尺寸”是否被正确区分。
- 模型是否因为工具/提示词限制而退化成两处安全换色。

请建立可执行的候选质量门或模型修正循环，但不要用固定故事、关键词表、房间专用 if/else 代替开放理解。质量门必须仍服从同一 canonical scene 与 SceneCommand 规则。

## P1：工具与资产能力可能限制了模型

当前工具能观察房间、对象与规则，并移动、旋转、改对象/表面材质、校验候选。请核对模型看到的观察是否足以理解门窗、进入视线、家具关系和可移动空间；不要假定问题只在系统提示词。

如果现有几何/工具不足以判断入口视线或成组布局，应扩展最小必要的结构化观察与工具，而不是让模型猜坐标。若要加入小件，必须来自真实可用 catalog/scene 能力；不能在回复里编造不存在的灯、椅子或欧派 SKU。

## P1：产品体验暴露内部实现

- “真实差异”抽屉会显示 `object-flex-bed`、`surface-wall-reference-10` 等内部 ID，录屏不自然。
- 等待约 30 秒时，需要明确的阶段反馈、取消与失败重试；不能让用户怀疑页面卡死。
- 首页进入工作台曾出现 `NOT_FOUND` 与 `HTTP_502`。相关修复已有提交 `cf9dd5b`、`9330ba7`，但必须作为冷启动回归，不能只验证已打开的旧项目。
- 家庭人数设置页仍存在，但首页路径绕过它。产品应保持个人使用完整成立；如恢复，只保留轻量、可跳过的居住背景，不把预算/风格问卷挡在 AI 对话前。

## 必须通过的行为验收

1. 原复现 A：不新增大件、保留书桌；结果必须对“像工位”产生明显且可解释的空间变化。允许先问一个真正影响方案的问题，但不能再问已知信息。
2. 约束语义对照：
   - “书桌要留”允许移动/旋转，禁止删除。
   - “书桌留在原位”禁止移动/旋转，仍可在许可下改材质。
   - “书桌什么都别动”禁止所有针对书桌的改动。
3. 同一句“想高级一点”，用户随后回答“主要想休息”“主要用于待客”“没有心理原因，只是不喜欢颜色”时，需求状态与方案必须分别分叉，且接受纠正。
4. 明确指令仍走快路径；模糊表达走真实模型理解，不能被正则提前挡住。
5. 非法多动作原子回滚；未保留的预览不覆盖已保存版本；刷新/重开一致。
6. 新的刁钻 holdout 输入不得复制演示措辞，首次失败也要计入结果。
7. 普通新会话从首页进入，不依赖已有 localStorage；API 暂时不可用时给出可恢复反馈，不落入永久 `NOT_FOUND/502`。
8. 桌面与手机视口完成真实浏览器点击验收；控制台无新增错误，主要资源真实加载。

## 不要做

- 不要为每个示例增加关键词或房间专用分支。
- 不要只调一版 system prompt 就宣布完成；用 A/B、真实 trace、反例和浏览器结果迭代。
- 不要改写/强推公开 `main`，不要提交 `.env.local`、token、真实客户数据或受限 Fab 二进制。
- 不要进行生产发布、真实飞书群发或真实客户数据修改。
