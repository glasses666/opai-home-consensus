# 元界视创｜20 分钟队友同步

更新时间：2026-09-09。目的：让不看代码的队友能在 20 分钟内说清产品、找到真实入口、完成各自验证任务。

## 一句话产品说明

OPAI 先用日常对话帮助一个人说清楚生活需求，再把已确认的需求变成同一套 3D 房屋里的真实、受约束、可撤销修改；用户保存方案后，才可以发起家庭讨论，由飞书收集和整理不同意见，用户自己决定采纳什么，结果再回到原项目形成新版本。

重点顺序是：**一个人也能完整使用的 AI 家装设计在前，家庭协作在后。** 飞书不是替家庭投票，也不是主模型；它承接多人意见、AI 摘要和版本留痕。

## 评委实际要看到什么

1. 用户可以说“这个客厅让我不想待”之类的模糊表达，而不是必须输入家具坐标。
2. AI 只追问一个真正影响方案的问题，或在信息足够时给出可撤销尝试。
3. 用户纠正“没有心理原因，只是不喜欢颜色”后，系统接受纠正，需求摘要和后续动作一起改变。
4. “工作桌必须保留”“不新增大件”“不能挡门”等确认条件跨轮有效。
5. 修改落到当前 3D 房屋中的真实对象；非法方案被规则拒绝，不污染已保存状态。
6. 用户能撤销、保留、保存并重新打开；来源、版本和实际模型身份可查。
7. 保存后可发起家庭讨论；飞书中的成员意见、Aily 摘要和用户最终选择分开记录，选择回到原项目后生成新版本。

当前隔离候选已验证真实 DeepSeek 的模糊输入、纠正、可撤销 3D 修改、保留保存与刷新重开，以及 Base 写读、真实 Aily 摘要和选择回流的新版本。最新闭环由同一隔离验收本人经 API 写入两条真实 Base 记录，Aily 比较的是两条意见内容，不能说成两个成员已参与；用户选择其中一条后，DeepSeek 观察实际对象关系，只移动茶几并保存 V5。手机真实 3D 与 Fab 材质变化已用电脑工具隐藏页检查；独立自由输入的首次失败和后续修正仍保存在验收账本中。现场若使用固定脚本、降级或录屏，必须标注。

## 20 分钟会议流程

### 0:00—3:00｜统一方向

- 主控用一句话介绍产品。
- 明确今晚不追求“页面更多、模型更多”，只追求一条完整、能让普通评委自由体验的闭环。
- 确认演示主叙事：“回到家才算下班”；它只是展示入口，系统不能依赖这句话触发。

### 3:00—8:00｜走一遍真实入口

- 打开主工作台，从一个全新项目/会话进入。
- 输入一条未硬编码的模糊生活表达。
- 看需求摘要、追问或尝试、3D 差异、撤销/保留、保存重开。
- 看已独立通过的隔离链路：发起讨论、两条测试记录同步、Aily 内容比较、用户选择和回流 V5。说明两条记录均由同一隔离验收本人填写，不说成多个真实家庭账号。

### 8:00—12:00｜对齐“能讲”和“不能讲”

- 能讲：当晚候选版本中已经真实验证、能被评委重复看到的行为。
- 不能讲：真实欧派 SKU、报价、BOM、工期、施工、生产接入；任意户型自动建模；未经试点验证的节省工时、减少返工或成交提升。
- 分清：DeepSeek 负责产品开放需求处理；飞书 Aily 负责多人意见整理；Astra/Sol 只是开发代理。
- 分清资料的两种身份：普通文字是带来源的参考；只有用户明确确认的 typed 规则才进入确定性执行约束。保留普通文字被模型误用的失败，不说任意文档都能约束设计。

### 12:00—17:00｜两位队友领取非技术任务

**队友 1：企业命题 / Coach / 业务验证**

- 向 Coach 或赛区助手确认：同一官方指引内部冲突的 7/8 分钟最终按哪个执行，以及提交入口、广州会议室和访客指引。
- 五项权重 30/25/20/20/5 已由官方指引附件复核；核对最新通知是否有变更即可，不再当作未知信息。
- 找回企业原始命题全文或截图，只摘录原话，不根据现有方案倒推。
- 与 Coach 确认一个可试点的真实品类、需要的交接字段和企业判断标准。
- 输出：一页核验表，逐项写“原文、来源链接/截图、确认人、确认时间、仍待确认”。
- 业务价值只提验证方法：需求遗漏数、重大修改轮次、确认用时、因需求/版本不清产生的交接退回；不得编试点数字。

**队友 2：自由体验 / 录屏 / 控时**

- 用普通新会话和新项目，不用开发者 localStorage 或隐藏参数。
- 自己说三类新表达：模糊感受、明确硬约束、对 AI 假设的纠正；记录首次结果，失败不能删。
- 完整录制一条从输入到保存重开的路径；飞书链路可用时再录后段回流。
- 记录等待、错误、重试、刷新和手机视口体验；录屏画面要能看清实际对象变化与 provider/source。
- 做两次计时试讲：7 分钟主稿目标 6:30—6:45；如 Coach 确认 8 分钟，再加入扩展段。
- 输出：一份失败清单、带时间码的完整录屏、两次试讲时长。

### 17:00—20:00｜确定下一次交付

- 主控给出候选 commit/工作区指纹和唯一体验入口。
- 队友 1 报告官方口径与企业命题核验缺口。
- 队友 2 报告自由体验中最影响理解的前三个问题。
- 三人只确定下一轮三个以内的关键修复或材料动作；不按功能数量扩张。
