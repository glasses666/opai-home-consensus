# 撰稿 Agent 探索清单

## 已经整理好，不必重新搜索

- 当前产品一句话定义、Demo 范围和不能宣称的能力；
- 当前自动测试、构建、provider、Aily/Base 和目录状态；
- 8 月 16 日研究档案与 9 月 7 日路演材料的位置；
- 家庭意见 UI 的信息层级与当前交互结构；
- 固定“加家具”录制场景与通用家具新增能力之间的边界；
- canonical scene、SceneCommand、规则、版本和家庭意见的技术主线。

## 收到最终 Demo 视频后必须探索

1. 逐段记录时间码、页面、用户动作、系统回应和肉眼可见变化。
2. 将每句旁白绑定到一个画面证据；没有画面或文档证据的句子标为待删/待补。
3. 检查实际出现的 provider 与“编排演示”标签，避免把固定场景误写为实时开放能力。
4. 记录卡顿、等待、重试、撤销、保存和重开是否真的入镜。
5. 给出建议剪掉的空等、重复滚动和无信息镜头，但不伪造成功路径。

## 只有这些情况才外部搜索

- 需要核对当前比赛的最新时长、提交格式或答辩规则；
- 需要找到欧派企业命题的原始官方表述；
- 某个行业事实缺少一手来源，而历史材料中也没有可核验出处。

外部搜索优先赛事、欧派、飞书等原始来源。不要为了让稿件“更丰富”新增无关行业数字，也不要引用搜索摘要代替原文。

## 交付文件

撰稿 Agent 最终应输出：

1. `01-七分钟主讲稿.md`：口语化、与录像时间码对应。
2. `02-镜头与操作提示.md`：谁操作、何时点击、哪里停留。
3. `03-答辩题库.md`：产品、技术、真实性、商业价值与限制。
4. `04-事实核对表.md`：每个关键主张的当前证据、来源日期和可说边界。
5. `05-待补证据.md`：只列会影响交付质量的缺口，不把未来功能变成赛前待办。

## 完成标准

- 不使用旧测试数字；
- 不把历史一次成功当作当前在线状态；
- 所有能力词都能在当前录像或当前事实表中找到依据；
- 主讲稿不出现 Harness、fixture、canonical ID 等面向开发者的词；
- 技术答辩附件可以使用上述术语，但要先给非技术解释；
- 加家具段明确写为固定、可复现的录制场景；
- 不把发行版能力塞回 Demo。
