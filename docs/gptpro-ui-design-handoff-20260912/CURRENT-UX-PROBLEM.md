# 当前 UI 问题合同

## 产品主线

产品的第一主线是：用户先独立说清生活需要，由 AI 将需要转成真实空间调整。家庭共创是保存方案之后的第二段能力：把不同成员的原始意见收回来，由飞书 AI 做有来源的整理，再由当前用户选择哪些意见返回设计助理。

家庭意见不能重新变成整个产品的唯一主线，也不能抢占个人设计的第一入口。

## 2026-09-12 当前浏览器实测

后台浏览器打开当前项目后，右侧默认显示「设计助理」。家庭入口位于右上角名为「切换」的菜单中，与「设计助理」「空间微调」并列。打开「家庭意见」后的空状态包含：

- 标题：「邀请家人一起看」；
- 副标题：「在你自己的方案之后，让不同意见有处可放」；
- 当前版本 `V1` 与「意见只属于这版方案」；
- 一段同时介绍需求简报、飞书、意见记录、飞书 AI 整理和带回机制的说明；
- 「给谁留意见栏」输入框，默认值「家人」；
- 一段关于邀请标签、作者核验、最近编辑者和权限的免责声明；
- 主按钮「为当前方案发起讨论」。

当前空状态没有触发任何真实飞书写入；该实测只读取和切换本地页面。

## 用户理解障碍

### 1. 入口可发现性弱

「切换」描述的是控件动作，不是用户目的。用户必须先猜出它会切换右侧工作区，再读三个模式，才能发现家庭意见。

### 2. 第一屏概念密度过高

用户尚未建立讨论，就同时遇到「版本」「需求简报」「飞书」「飞书 AI」「意见栏」「邀请标签」「身份作者」「权限」。安全说明是必要的，但与主任务同等权重，压住了真正的下一步。

### 3. 端到端心智模型不可见

真实流程是：

`保存方案 → 发起讨论 → 家人分别表达 → 同步 → AI 整理 → 用户选择 → 返回设计助理 → 预览 → 保留/保存新版本`

当前界面主要展示当前局部操作，用户很难预判发起讨论后会发生什么、何时回到产品、什么才算完成。

### 4. 角色与权限解释正确但不自然

当前实现严谨地区分：邀请称呼、实际填写者、表格最近编辑者、AI 摘要、用户采纳。但这些边界被写成长段制度说明，客户容易把它理解成系统很复杂或“还不能用”。

目标不是删掉边界，而是按需展示：主流程使用自然语言，证据与权限进入可展开的「来源与权限」层。

### 5. “意见”和“决定”缺少视觉分层

成员原话、AI 归纳、共同主题、记录差异、待明确项和用户勾选，属于不同可信度与决策阶段。当前主要靠标题和小字区分，扫读时仍容易混为一谈。

### 6. 版本绑定重要，但表现方式过于技术化

「意见只属于这版方案」是核心安全规则；用户需要理解“新版本不会自动继承旧意见”。但版本 ID 不应成为主角。更自然的表达可以是“正在讨论：当前已保存方案 V3”，并在版本变化时给出清晰的过期/新建讨论选择。

### 7. 长状态在 330px 侧栏内会产生滚动疲劳

后续状态包含：意见入口、意见槽、原始意见、自己补充、同步、AI 整理、四类摘要、来源回查、勾选与带回。全都纵向堆叠会让用户丢失当前位置和下一步。

### 8. 移动端需要重新组织，不是简单压缩

桌面右侧栏在移动端会进入页面下方。六套方案都必须说明移动端的信息顺序、固定动作和返回设计的方式，不能只把桌面卡片变窄。

## 需要 GPTPro 回答的设计问题

- 家庭入口应怎样既容易找到，又不抢个人设计主线？
- 如何用 1–2 句话让客户理解发起讨论会发生什么？
- 原始意见、AI 整理和用户决定如何一眼区分？
- 如何让“当前需要我做什么”始终可见？
- 状态多、证据多时，侧栏、抽屉、全页或分步界面怎样分工？
- 如何在不隐藏真实边界的情况下，把法律/身份/权限说明放到恰当层级？
- 旧版本、同步失败、无飞书入口、空意见和部分来源缺失如何诚实但不吓人地展示？

## 不是目标的“优化”

- 只换颜色、圆角、图标或阴影；
- 把所有内容做成更多卡片；
- 用一个进度条包住原有纵向列表；
- 让 AI 自动替家庭做决定；
- 用虚构成员头像、虚构已读状态或虚构实时在线制造热闹；
- 把飞书 AI 结果改写成 DeepSeek 结果；
- 为了更简洁而删除来源、版本或采纳边界。
