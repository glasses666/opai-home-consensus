# 给 GPTPro 的主提示词

请接手 OPAI「我的生活空间」的家庭意见 UI 设计改造。当前功能的业务链路基本完整，但普通客户不容易快速理解入口、流程、AI 的作用，以及最后由谁决定。请使用充分的时间（预期 2–3 小时以上）自行研究、探索、编码、试错和验证，不要在给出计划或分析后停止。

## 目标

先研究真实优秀产品的相关交互，再提出并实现至少 6 套前端设计方案。方案之间应在信息层级、交互结构或用户心智模型上有实质差异，不能只是换颜色、圆角或排版。

每套都要有可运行的前端代码，并保持与当前网站整体视觉语言相近。完成探索后，请推荐你认为最好的方案或组合，并给出可合并回当前项目的实现代码。

## 你可以自由决定

你可以自行决定：

- 研究哪些产品、找多少参考，以及如何提炼模式；
- 家庭意见入口怎样呈现；
- 使用侧栏、抽屉、全页、步骤流或其他结构；
- 六套方案的具体方向；
- 组件拆分、状态组织、评估方式和推荐标准；
- 是否组合不同方案的优点。

`REFERENCE-SEEDS.md` 和 `SIX-DIRECTION-BRIEF.md` 只是帮助起步的可选材料，不是指定答案，也不要求照着其中方向实现。

## 必须保留的边界

1. 个人设计是主线，家庭讨论发生在用户已有保存方案之后，不能反过来成为唯一入口。
2. 每次讨论属于一个明确的已保存版本；旧版本意见不能静默套用到新版本。
3. 成员原始意见、飞书 AI 的整理、当前用户的选择必须清楚区分。
4. 飞书 AI/Aily 只负责有来源的整理，不能替家庭决定，也不能直接修改 3D 场景。
5. 只有用户明确选择并带回的意见，才交给设计助理生成可撤销预览；带回不等于已经保存。
6. 摘要应能回查原意见；缺少来源的内容不能当作可采纳结论。
7. 邀请称呼不等于已核验身份，表格最近编辑者也不等于意见作者。界面可以渐进披露这些说明，但不能制造虚假身份、权限、实时状态或 AI 成功。
8. 不修改或重做 3D 房间、家具模型、材质、相机和场景编辑能力。候选设计可将 3D 区域视为固定黑盒或中性占位。
9. 不读取、上传或输出 `.env.local`、密钥、真实客户数据；不向真实群聊或飞书表发送内容。
10. 不直接覆盖远端 `main`。请以独立目录、分支、补丁或 ZIP 交付。

更完整的现有业务和技术事实在 `DESIGN-CONTRACT.md`、`CURRENT-UX-PROBLEM.md`、当前源码与测试中。若你认为现有界面结构本身有问题，可以大胆重构前端；只需保持上述产品真相和已有对外行为。

## 视觉关系

方案不能与当前整站风格明显割裂。请先阅读现有 CSS 与截图，理解其暖白/米白、深橄榄灰绿、少量陶土红、中文衬线标题、安静编辑式家居感，再决定如何发展这套语言。

不要简单套用通用 AI SaaS 模板。除此之外，视觉和交互探索空间由你决定。

## 输入材料

- `CURRENT-UX-PROBLEM.md`：当前浏览器观察与理解障碍。
- `DESIGN-CONTRACT.md`：现有业务、状态和 API 边界。
- `source/app/src/ExperienceDiscussion.jsx`：当前真实家庭意见 UI。
- `source/app/src/App.jsx`：工作台入口、设计助理回流、复核与交接。
- `source/app/src/*.css`：当前整站视觉语言。
- `fixtures/family-discussion-states.json`：可用于设计演示的脱敏状态。
- `evidence/`：当前整体界面和历史探索证据；历史图不是当前实现。
- `FILE-MAP.md`：文件用途。

包内 `source/` 是当前本地工作树快照。若远端仓库同名文件不同，以包内版本作为这次设计任务的基准。

## 交付要求

请至少交付：

- 一份可回查链接与设计启发的参考研究；
- 至少 6 套可运行、可切换或可分别打开的前端方案；
- 各方案的桌面和手机实际效果；
- 对关键状态的呈现，包括未发起、收集意见、AI 整理、用户选择带回、旧版本和失败/恢复；
- 对六套方案的比较与最终推荐理由；
- 推荐方案的可合并 React/CSS 代码；
- 构建、交互、响应式、键盘操作和控制台检查结果；
- 变更文件清单，以及分支、补丁或 ZIP。

可以使用脱敏 fixture 完成六套 UI 探索，不需要调用真实 DeepSeek、飞书或 Aily。最终说明中请准确区分“设计沙盒可运行”“已并入完整产品”“真实外部服务已验证”，不要互相冒充。

现在开始。先理解当前产品并完成参考研究，然后持续实现和迭代，直到六套设计代码、推荐方案和验证结果都齐全。
