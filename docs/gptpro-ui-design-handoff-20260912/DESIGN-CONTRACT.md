# 设计与产品合同

## 必须保留的产品真相

1. 个人设计完整成立，家庭讨论发生在已保存方案之后。
2. 每次家庭讨论绑定一个明确的已保存版本；旧版本意见不得静默套用到新版本。
3. 成员原始意见、飞书 AI 整理、当前用户的选择是三个不同层次，不能混写。
4. 飞书 AI/Aily 只读整理意见，不能直接修改 3D 场景、替家庭确认或自动采纳。
5. 只有当前用户明确选中并点击带回的内容，才能生成给设计助理的调整请求。
6. 带回后仍要走同一个设计助理流程：预览、校验、撤销/保留、保存新版本。
7. 所有摘要项都必须能回查原始意见；缺来源的项不能被采纳。
8. 邀请标签不是已验证身份；表格最近编辑者也不等于意见字段作者。
9. 没有当前证据时不能声称实时多人、权限已授予、飞书已写入或 Aily 已完成。
10. 失败、超时、旧版本和授权失效都必须保留当前方案并给出可恢复动作。

## 当前 API/交互合同（不能因视觉方案而破坏）

`ExperienceDiscussion` 接收：

- `path`
- `headers`
- `versionId`
- `versionLabel`
- `requirements`
- `disabled`
- `onAdopt({ request, discussionId, baseVersionId })`

现有请求族：

- `GET {path}/discussions?versionId=...`
- `POST {path}/discussions`
- `GET {path}/discussions/{discussionId}`
- `POST {path}/discussions/{discussionId}/sync`
- `POST {path}/discussions/{discussionId}/opinions`
- `POST {path}/discussions/{discussionId}/summarize`
- `POST {path}/discussions/{discussionId}/adopt`

请求已有稳定 `eventId`、同屏单操作锁、90 秒总超时、版本作用域失效和迟到结果保护。设计代码不得为了演示绕开这些机制。

## 必须覆盖的 UI 状态

- 加载当前版本讨论；
- 未发起讨论；
- 当前方案有未保存预览，讨论不可用；
- 正在建立讨论；
- 已建立但尚无可用飞书入口；
- 已建立并可打开飞书；
- 尚未收到意见；
- 已收到一条/多条原始意见；
- 正在同步；同步成功；同步失败/授权失效；
- 当前用户补充自己的意见；
- 正在由飞书 AI 整理；
- Aily 摘要完成；系统安全说明；摘要失败；
- 共同主题、意见记录差异、已表达意向、待明确；
- 有来源可选择、来源丢失不可选择；
- 已勾选但未带回；正在带回；已交给设计助理；
- 版本已变化/讨论过期；
- 重复点击、取消或迟到响应不重复产生动作；
- 桌面 1440×900、常见 1024 宽度、手机 390×844。

## 视觉语言

必须延续当前 OPAI 网站：

- 暖白/米白工作面；
- 深橄榄灰绿作为结构和主动作；
- 陶土红只作克制强调；
- 宋体/衬线标题与干净的中文无衬线正文；
- 编辑式、安静、家居目录感；
- 细分隔线、少量小半径，不追求大量悬浮卡片；
- 文案是自然中文，不使用“Harness”“Agent loop”等内部术语。

避免：蓝紫渐变、霓虹、玻璃拟态、聊天机器人气泡堆叠、过量胶囊、通用 SaaS 仪表盘、卡通家庭头像墙、与当前首页完全不同的品牌色。

## 3D 边界

本任务不设计、不修改、不复制：房间结构、家具模型、相机、灯光、材质、坐标、编辑手柄或 3D 性能。候选演示中将左侧 3D 区域做成固定的中性占位舞台即可；真实集成时仍由现有 3D 组件提供。

允许设计与 3D 的交互关系，例如“某条意见指向主卧床头墙”，但只能使用已有房间/对象标签和来源，不得发明新的场景编辑能力。

## 可访问性与响应式底线

- 可用键盘完成切换、选择、展开来源和提交；
- 焦点可见；
- 图标不能是唯一含义；
- 状态不能只靠颜色；
- 正在处理和结果用合适的 `aria-live`/`role=status`；
- 点击区不因 330px 侧栏而过小；
- 手机端主动作可见，但不能遮挡内容；
- 尊重 `prefers-reduced-motion`；
- 文本缩放与长中文不溢出。

## 技术边界

- 当前栈：React 19、Vite 8、普通 CSS、Phosphor Icons/Lucide；
- 不引入新的 UI 框架、状态框架或设计系统依赖；
- 六套探索可以共享夹具和基础 token，但 DOM/信息架构必须真正不同；
- 最终推荐实现应能替换或重构 `ExperienceDiscussion.jsx`，不要求后端改协议；
- 不读取、不输出、不提交 `.env.local` 或任何密钥；
- 不直接修改远端 `main`。
