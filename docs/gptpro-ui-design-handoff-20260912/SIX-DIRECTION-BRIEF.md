# 六个可选结构种子

本页只是帮助起步的灵感，不是任务约束或预先指定的答案。GPTPro 可以全部舍弃，自行提出更好的方向。最终只需保证至少六套方案在信息架构、主要动作或阅读顺序上真正不同，而不是同一 DOM 换主题。

## A. 引导式旅程

把家庭讨论表现为一段很短的旅程：准备方案、邀请表达、查看意见、AI 整理、选择带回。当前步骤和下一动作始终清楚，历史步骤压缩。研究如何避免传统企业表单式 stepper 的僵硬。

## B. 家庭收件箱

把“意见”作为待处理收件箱：谁还没表达、哪些是新意见、哪些需要我决定、哪些已带回。第一屏突出未完成任务，来源和版本进入详情。研究 Notion/Slack 的未读与归档，但用家庭语气而不是办公语气。

## C. 决策桌面

以四个区块组织：大家都在意、意见不一样、还需问清、我的决定。原始意见作为证据从每项展开。适合摘要完成后快速决策，但必须同时设计摘要前的自然空状态。

## D. 空间旁注

按房间/对象组织意见，例如“主卧床头墙 2 条”“客餐厅动线 3 条”。右侧先显示空间清单，点开才看成员原话和 AI 整理。即使没有画布锚点，也要让空间对象和意见关系直观；不能改 3D。

## E. 家庭简报

像一页面向普通客户的简短家庭简报：一句当前状态、成员原话摘录、AI 帮你归纳、最后请你选择。强调阅读与理解，不把所有能力都放成常驻控制。研究编辑式长页如何在手机上保持节奏。

## F. 简洁主层 + 证据抽屉

主层只保留当前任务、必要摘要和动作；版本、来源、身份、权限、同步日志进入明确可见但默认收起的证据抽屉。重点验证“渐进披露”是否既减压又不掩盖限制。

## 每套必须包含

- 桌面和手机；
- 未发起、收集中、已有意见、AI 整理、选择带回、完成/过期、失败状态；
- 一句话解释为什么普通客户比现状更容易理解；
- 其主要参考、借用的模式和主动舍弃的模式；
- 实际 React/CSS 代码；
- 独立可访问路由或切换器；
- 与 `ExperienceDiscussion` API 合同的映射；
- 已知取舍。

## 推荐方案

完成六套并在浏览器验证后，再推荐一个方案或明确的混合方案。推荐不能只凭“更漂亮”，至少比较：首次任务理解、流程可预期性、意见/摘要/决定区分、来源可信度、版本理解、侧栏效率、手机可用性、实现风险。
